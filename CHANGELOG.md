# Changelog

All notable changes to boilerlift are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the version is below 1.0, a minor version can contain breaking changes.

Each release adds its section below this line, newest first, as `## [X.Y.Z] - YYYY-MM-DD`. The release skill writes it (`.claude/skills/release/SKILL.md`): do not edit this file by hand in a feature pull request.

## [0.2.0] - 2026-11-22

### Added

- `lift init` starts a project in one command, in an empty folder: a `dev` target, an example workflow with a tested Code node, `npm run verify` (ESLint, TypeScript, Vitest), `npm run n8n` for one call to the n8n API without printing the key, and an Agent kit (`AGENTS.md`, skills and a Claude Code hook that asks before publishing, cleaning, resetting or deploying outside `dev`, and never reads `.env`).
- `lift status` shows where each workflow of a target stands on its instance (missing, archived, differs, draft not yet published, up to date, removed) and the next command to run. `--managed`, `--archived` and `--json` filter and format it. It only reads.
- `lift publish` publishes the drafts `deploy` delivered, all of them or only the named ones, after one `[Y/n]` question (`--yes` skips it). A workflow changed in the n8n editor is reported and not published.
- `lift creds sync` writes the credentials of each target's instance to `credentials/<target>.ts` (key, name, type and id, never a secret) and reports the credentials your workflows use that the target does not have.
- `credential('key')` picks a credential in a workflow file, with editor autocompletion. `deploy` resolves it from the list of the target being deployed, so one workflow deploys to `dev` with the dev credential and to `prod` with the prod one, and stops a target before any write when a credential is missing.
- `lift clean` archives, after confirmation, the workflows you removed from the project and drops them from `boilerlift.lock.json`. `--delete` deletes them for good instead, and `--dry-run` only lists them.
- `lift reset --target <name>` archives (or with `--delete`, deletes) every workflow Boilerlift deployed on one target, after you type the target name, to leave a test server clean or undo a deploy to the wrong environment.
- `deploy` tags each workflow it delivers with `boilerlift:<target>`, so n8n shows which target it belongs to. Set `tag: false` on a target to turn it off.
- `deploy`, `publish` and `status` show each workflow's link to the n8n editor, so a ctrl+click opens it. With `--json`, each result carries it as `url`.

### Changed

- **Breaking:** a target name is now 1 to 13 lowercase letters, digits or dashes, so its `boilerlift:<target>` tag fits an n8n tag name. A config with a longer name must rename the target.
- Every command prints its output in one consistent style, with colour in a terminal. `NO_COLOR` turns colour off and `FORCE_COLOR` turns it on; `--json` output is never coloured.
- `deploy` and `status` recommend `lift publish` as the next step after a draft is delivered.

## [0.1.0] - 2026-11-19

### Added

- The `lift` command (`boilerlift` is an alias), installed with `npm install -g boilerlift`, with `lift help`, `lift help <command>` and `lift version`.
- Typed workflow files: `defineWorkflow` from the `boilerlift` package lets you write workflows as `.workflow.ts` files, next to `.json` workflows exported from n8n.
- `boilerlift.config.ts` with `defineConfig`: declare one or more targets, each with its n8n `url`, `apiKey` (read from `process.env`, so it can come from `.env`) and workflows folder.
- `lift ping` checks the connection and the API key for a target, chosen with `--target` (`-t`) or every target with `--all`, and can print its checks as JSON with `--json`.
- `lift deploy` checks every workflow file before anything is sent, then delivers each workflow to its target as a draft: the published version keeps running until you publish it in n8n. Unchanged workflows are skipped, so a rerun changes nothing.
- `lift deploy --dry-run` shows what a deploy would do without writing anything, and `--json` prints the report for scripts and AI agents. `--target` and `--all` choose the targets as for `ping`.
- `boilerlift.lock.json` records the n8n id of each workflow `deploy` creates, so later deploys find it by id, never by name or tag. Workflows the lock file does not list are never touched, so several projects can share one instance.
- `deploy` handles unexpected states safely: it stops on an instance too old to save drafts, restores a workflow archived in n8n as an unpublished draft, creates again a workflow n8n no longer has, and keeps delivering the other workflows when one fails.
