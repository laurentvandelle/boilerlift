# Changelog

All notable changes to boilerlift are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the version is below 1.0, a minor version can contain breaking changes.

Each release adds its section below this line, newest first, as `## [X.Y.Z] - YYYY-MM-DD`. The release skill writes it (`.claude/skills/release/SKILL.md`): do not edit this file by hand in a feature pull request.

## [0.1.0] - 2026-11-19

### Added

- The `lift` command (`boilerlift` is an alias), installed with `npm install -g boilerlift`, with `lift help`, `lift help <command>` and `lift version`.
- Typed workflow files: `defineWorkflow` from the `boilerlift` package lets you write workflows as `.workflow.ts` files, next to `.json` workflows exported from n8n.
- `boilerlift.config.ts` with `defineConfig`: declare one or more targets, each with its n8n `url`, `apiKey` (read from `process.env`, so it can come from `.env`) and workflows folder.
- `lift ping` checks the connection and the API key for a target, chosen with `--target` (`-t`) or every target with `--all`, and can print its checks as JSON with `--json`.
- `lift deploy` checks every workflow file before anything is sent, then delivers each workflow to its target as a draft: the published version keeps running until you publish it in n8n. Unchanged workflows are skipped, so a rerun changes nothing.
- `lift deploy --dry-run` shows what a deploy would do without writing anything, and `--json` prints the report for scripts and AI agents. `--target` and `--all` choose the targets as for `ping`.
- `boilerlift.lock.json` records the n8n id of each workflow `deploy` creates, so later deploys find it by id, never by name or tag. Workflows the lock file does not list are never touched, so several projects can share one instance.
- `deploy` handles unexpected states safely: it stops on an instance too old to save drafts, restores a workflow archived in n8n as an unpublished draft, creates again a workflow n8n no longer has, and keeps delivering the other workflows when one fails.
